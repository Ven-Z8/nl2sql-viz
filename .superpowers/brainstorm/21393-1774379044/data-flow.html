Query Lifecycle — End to End

How a natural language question becomes a live chart

Flow: "Show me monthly revenue by region for Q1"
1️⃣
User types query in browser
Frontend sends via WebSocket → FastAPI receives, creates a session context, dispatches to Coordinator Agent
~50ms
↓
2️⃣
Coordinator Agent starts agentic loop
Determines intent → calls Schema Agent tool first. Streams "Analyzing your database..." to UI.
~200ms
↓
3️⃣
Schema Agent explores DB
Reads table names, column types, foreign keys. Builds a compact schema map. Caches it for the session.
~300ms
↓
4️⃣
SQL Agent writes & executes query (agentic loop)
Writes SQL → runs it → checks result shape → if wrong, rewrites and retries (max 3x). Streams SQL to UI for transparency.
~500ms–2s
↓
5️⃣
Code Exec Agent (BUN) — only if needed
If data needs transformation (rolling avg, pivot, percentile), Claude writes a BUN script → runs sandboxed → outputs shaped data. Skipped for simple queries.
~300ms (optional)
↓
6️⃣
Viz Agent generates Vega-Lite spec
Picks best chart type for the data (bar, line, scatter, heatmap…). Generates full Vega-Lite JSON. Adds title, axis labels, colors.
~400ms
↓
7️⃣
WebSocket streams result to browser
Vega-Lite JSON sent → vega-embed renders chart instantly. User also sees the SQL used, raw data table, and can pin the chart to a dashboard.
~50ms render
Total end-to-end (simple query): ~1–2 seconds  |  Complex query with BUN: ~2–4 seconds

Real-time Modes

🔵 Live Query Mode
User asks a question → runs now against current DB state. Always fresh. No caching.
🟢 Stream Mode (CDC/Kafka)
Changes in DB trigger Debezium CDC → Kafka topic → our consumer pushes updated viz to all subscribed WebSocket clients automatically.
🟡 Scheduled Refresh Mode
Dashboard pinned charts re-run their query every N seconds/minutes. Scheduler triggers the SQL Agent directly, no NL needed.
