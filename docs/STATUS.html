Known Issues / Tech Debt
🔴
SQLAgent + VizAgent use sync Anthropic() — blocks the event loop under concurrent load
Fix target: Plan 2.5 — swap to AsyncAnthropic()
🔴
_users dict is in-memory — all sessions are lost on restart
Fix target: Plan 2.5 — SQLite session store behind an interface
🟡
DSN passed raw in WebSocket messages — potential SSRF risk if untrusted clients connect
Fix target: Plan 4 — DB connection wizard with server-side DSN registry
🟡
No rate limiting or per-request timeouts — a slow query can hold a WebSocket open indefinitely
Fix target: Plan 2.5 — 30s wall-clock timeout + N queries/min per session
🟢
security.py (AES-256-GCM encryption) is built and tested but currently unused
Ready to activate in Plan 4 for encrypted DSN storage
Plan 2.5 — What's Being Built Now
Task 1
Async Clients
Replace Anthropic() with AsyncAnthropic() in sql_agent.py and viz_agent.py. Eliminates the sync bottleneck so the FastAPI event loop stays non-blocking under concurrent WebSocket connections.
Task 2
SQLite Session Store
Abstract _users and session data behind a clean interface, backed by SQLite. Sessions survive process restarts and can later be swapped to Postgres without touching agent code.
Task 3
Request Guard
30-second wall-clock timeout per WebSocket request. Rate limit of N queries/minute per session. Protects against runaway queries and basic abuse without needing a full API gateway.

WebSocket Protocol
message · sequence
CLIENT → {"type": "auth", "api_key": "..."}
SERVER → {"type": "authenticated", "user_id": "..."}
CLIENT → {"type": "query", "query": "...", "dsn": "postgresql://..."}
SERVER → {"type": "progress", "message": "..."} ← multiple
SERVER → {"type": "sql", "sql": "SELECT ..."}
SERVER → {"type": "result", "vega_spec": "...", "sql": "..."}
SERVER → {"type": "error", "message": "..."} ← on failure
